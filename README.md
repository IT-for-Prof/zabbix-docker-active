# Docker by Zabbix agent 2 active

> Шаблон Zabbix 8.0: официальный «Docker by Zabbix agent 2» на активных проверках, для хостов за NAT.

Агент сам отправляет данные серверу или прокси, поэтому входящий порт 10050 на хосте не нужен.
Шаблон собирается скриптом `build.py` из официального YAML Zabbix, поэтому новая ревизия
официального шаблона превращается в новую сборку клона одной командой.

Этот файл описывает русскую версию, `template_app_docker_agent2_active.yaml`. Английская версия того
же шаблона — `template_app_docker_agent2_active_en.yaml`, её описывает [README_EN.md](README_EN.md).
Версии различаются только нашими текстами: описанием шаблона и добавленным триггером. UUID и имя у них
общие, поэтому импорт любой из них обновляет установленный клон на месте, с сохранением истории.

## Зачем

Официальный шаблон опрашивает агента с сервера или прокси. Хосту за NAT для этого нужен проброс порта
10050 снаружи, и чаще всего его нет. Zabbix сам выпускает активные варианты для части шаблонов,
например `MySQL by Zabbix agent 2 active` и `PostgreSQL by Zabbix agent 2 active`. Для Docker такого
варианта нет. Клон собран по тому же рецепту: ключи, триггеры и макросы те же, опрашиваемые объекты
становятся активными, UUID новые.

## Что отличается от официального

| Что | Как в клоне |
|---|---|
| 9 объектов, которые сервер опрашивал сам: `docker.info`, `docker.containers`, `docker.images`, `docker.data_usage`, `docker.ping`, два правила LLD, прототипы `docker.container_info[…,full]` и `docker.container_stats[…]` | `ZABBIX_ACTIVE`; остальные элементы зависимые и не меняются |
| `docker.volumes_size`, `docker.containers_size`, `docker.images_size` | при пустом массиве значение 0. В официальном шаблоне агрегат JSONPath `.sum()` на пустом массиве падает, и на хосте без томов, контейнеров или образов элемент не поддерживается (ошибка Zabbix [ZBX-19277](https://support.zabbix.com/browse/ZBX-19277)) |
| Триггеры | официальные плюс один, раздел «Триггеры» |
| UUID | новые, выводятся из UUID официального шаблона: импорт клона не трогает официальный шаблон, повторная сборка даёт те же UUID |
| Имя | `Docker by Zabbix agent 2 active (Custom)`, техническое — `Docker by Zabbix agent 2 active Custom` |
| Группа, vendor | `Templates/Applications` и vendor официального шаблона (`Zabbix`, `8.0-2`): по vendor видно, из какой версии собран клон. Версия сборки и автор — в конце описания шаблона |
| readme и wizard | не переносятся: они описывают пассивный шаблон |

Исходник — `templates/app/docker/template_app_docker.yaml` из
[репозитория Zabbix](https://git.zabbix.com/projects/ZBX/repos/zabbix/browse/templates/app/docker),
ветка `release/8.0`, коммит `22c39f0ccbf4434dbdfe2362a88c4102da25a556`, vendor version 8.0-2.
Он лежит без изменений в `upstream/`.

## Триггеры

Официальные триггеры не меняются: «Failed to fetch info data», «Service is down», «Version has
changed» и три прототипа по контейнерам. Добавлен один:

| Триггер | Важность | Когда срабатывает |
|---|---|---|
| Docker: данные о размерах не приходят | Warning | образы на хосте есть (`docker.images.total` больше 0), а `docker.layers_size` равен 0 дольше 10 минут |

Плагин Docker агента разбирает ответ `/system/df` в свою структуру и всегда отдаёт массивы томов,
контейнеров и образов. Docker 29 объявил эти поля устаревшими. Если Docker их уберёт, агент отдаст
пустые массивы, и все размеры станут 0. Триггер ловит именно этот случай, исправляется он обновлением
плагина агента.

Триггер зависит от «Docker: Service is down». Если агент недоступен, данных в окне нет, триггер
переходит в состояние «неизвестно» и не срабатывает. Об отказе агента сообщает шаблон ОС, например
«Linux by Zabbix agent active».

## Требования

- Zabbix server 8.0. Прокси, через которую идёт хост, работает на той же основной версии. Устаревшая
  прокси, например 7.0 при сервере 8.0, данные собирает, но новую конфигурацию не получает. На хостах
  за ней клон не действует, и элементы собираются по прежней конфигурации.
- Zabbix agent 2 с плагином Docker. Проверено на агентах 7.0 и 8.0.
- Пользователь агента состоит в группе `docker`. Это права root на хосте.
- В конфиге агента задан `ServerActive`, а `Hostname` совпадает с именем хоста в Zabbix.

Проверка на хосте: `zabbix_agent2 -t docker.info` возвращает JSON с `ServerVersion`.

## Установка

1. Импортировать один из двух файлов (Data collection → Templates → Import). Через API сначала
   посмотреть изменения в `configuration.importcompare`.
2. Привязать шаблон к хосту. С официальным шаблоном на одном хосте клон не привязывается, потому
   что у них одинаковые ключи. Переход описан в следующем разделе.
3. Проверить через минуту: у `docker.ping` значение 1 и свежее время значения.

## Переход с официального шаблона

С сохранением истории:

1. Отвязать официальный шаблон без очистки: `host.massremove` с `templateids`. Элементы остаются на
   хосте.
2. Привязать клон: `host.massadd`. Zabbix свяжет элементы, правила LLD и обнаруженные элементы по
   ключу, itemid и история сохранятся.
3. Проверить: число элементов `docker.*` на хосте и их itemid совпадают с прежними. Обнаруженные
   элементы станут активными на следующем проходе LLD, в пределах 15 минут.

Без сохранения истории официальный шаблон отвязывается с очисткой, затем привязывается клон.
Пропадут история и открытые проблемы, LLD заново обнаружит контейнеры.

Откат выполняется в обратном порядке: отвязать клон без очистки и привязать официальный шаблон.

## Макросы

Те же, что у официального шаблона.

| Макрос | По умолчанию | Назначение |
|---|---|---|
| `{$DOCKER.LLD.FILTER.CONTAINER.MATCHES}` | `.*` | какие контейнеры обнаруживать |
| `{$DOCKER.LLD.FILTER.CONTAINER.NOT_MATCHES}` | `CHANGE_IF_NEEDED` | какие контейнеры исключить |
| `{$DOCKER.LLD.FILTER.IMAGE.MATCHES}` | `.*` | какие образы обнаруживать |
| `{$DOCKER.LLD.FILTER.IMAGE.NOT_MATCHES}` | `CHANGE_IF_NEEDED` | какие образы исключить |

## Чего шаблон не ловит

- Хосты за устаревшей прокси. Шаблон там не применяется, а Zabbix об этом не предупреждает: проверить
  можно в `proxy.get`, где у такой прокси `compatibility` равен 2.
- Медленный `/system/df`. Если Docker не отвечает за тайм-аут агента, все четыре элемента размеров
  не поддерживаются. Причина на стороне Docker, шаблон её не показывает.
- Удаление полей `/system/df` в Docker до того, как пройдут 10 минут окна триггера: в это время
  размеры показывают 0.
- Названия элементов и официальных триггеров остаются английскими в обеих версиях: перевод
  195 объектов мешал бы пересобирать клон из новой ревизии официального шаблона.

## Сборка и обновление

```bash
curl -o upstream/template_app_docker.yaml \
  'https://git.zabbix.com/projects/ZBX/repos/zabbix/raw/templates/app/docker/template_app_docker.yaml?at=refs%2Fheads%2Frelease%2F8.0'
python3 build.py
python3 -m pytest -q
```

`build.py` собирает обе версии и отказывается записывать файл, если:

- пропал ключ или остался пассивный элемент;
- выжил UUID официального шаблона;
- поменялись макросы;
- предобработка элемента отличается от официальной, кроме трёх элементов размеров;
- зависимость добавленного триггера не нашлась в шаблоне.

Тесты проверяют ещё, что файлы в репозитории совпадают со свежей сборкой и что две версии
различаются только нашими текстами.

Нужен Python 3 с PyYAML. Для Zabbix 7.x в `upstream/` кладётся шаблон из ветки `release/7.x`.
Такую сборку мы не проверяли.
